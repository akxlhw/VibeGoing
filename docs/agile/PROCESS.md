# VibeGoing 敏捷开发流程与工程规范

> 本文档是项目的开发宪法：角色与节奏、工作流、质量门禁、完成的定义（DoD）。
> 所有代码变更必须遵守此处约定。路线图背景见 [PLAN.md](../../PLAN.md)，当前待办见 [BACKLOG.md](BACKLOG.md)。

## 1. 角色与协作

| 角色 | 承担者 | 职责 |
|---|---|---|
| 产品负责人（PO） | 用户 | 定优先级、验收里程碑、拍板开放问题 |
| 开发（Dev） | AI 助手（ZCode） | 拆故事、实现、测试、文档、发起评审 |
| 流程裁判 | 本文档 | 任何分歧以 PROCESS.md 为准，修订需单独提交并说明理由 |

单人 + AI 的微型团队采用**精简 Scrum**：保留冲刺、待办、评审与回顾，去掉站立会（以冲刺文档中的进度表代替）。

## 2. 节奏与仪式

- **冲刺长度**：1 周（周一启动，周五收口）
- **冲刺计划**（周一）：从 BACKLOG 认领故事，写入 `docs/agile/sprints/<日期>_S<n>.md`，锁定目标与验收
- **冲刺评审**（周五，面向 PO）：对照验收标准逐条演示；未完成项回退 BACKLOG 并注明原因
- **回顾**（周五，面向流程）：每个冲刺文档末尾记录 *继续做 / 停止做 / 开始做* 各至少一条
- **里程碑（M1–M5）**：由 1–2 个冲刺构成，对应 PLAN.md；里程碑完成需 PO 验收全部验收标准

## 3. 需求管理

- 所有工作以**故事（Story）**为单位，编号 `VG-<序号>`（如 VG-101），登记在 [BACKLOG.md](BACKLOG.md)
- 故事卡片字段：`编号 | 史诗 | 描述（作为…我希望…以便…） | 验收标准 | 估点 | 优先级 | 状态`
- 估点用斐波那契（1/2/3/5/8），1 点 ≈ 半人日的实现+测试+文档
- 状态流转：`待办 → 进行中 → 待验收 → 完成 / 退回`；状态只允许在冲刺收口或 PO 验收时批量更新
- 缺陷以 `VG-9xx` 编号登记，P0（阻塞核心功能）可打断冲刺，其余进 BACKLOG 排队

## 4. 分支与提交规范

- `main` 为受保护分支：**所有变更经特性分支进入**，禁止直接推送（流程引导类的一次性 bootstrap 除外）
- 分支命名：`feature/VG-101-session-persistence`、`fix/VG-903-memory-crash`、`docs/…`、`chore/…`
- 提交信息用约定式提交：`type(VG-xxx): 摘要`，type ∈ feat / fix / docs / refactor / test / chore / ci
- 合并方式：GitHub 上发起 PR → CI 全绿 → 自审通过 → squash merge，提交信息保留故事编号

## 5. 质量门禁（Definition of Done 的硬性部分）

每次 PR 必须全部通过，本地与 CI 同口径：

| 门禁 | 命令 | 要求 |
|---|---|---|
| 静态检查 | `uv run ruff check .` | 0 违例（中文全角标点误报已在配置豁免） |
| 格式化 | `uv run black --check .` | 无 diff |
| 类型检查 | `uv run mypy` | 0 error（产品代码全覆盖，测试目录暂不纳入） |
| 单元测试 | `uv run pytest` | 全绿；新功能必须带行为测试（测行为不测实现） |
| 文档 | — | CHANGELOG 更新；公共 API 有 docstring；涉及架构决策时新增 ADR |

## 6. 完成的定义（Definition of Done）

一个故事只有同时满足以下条件才算"完成"：

1. §5 质量门禁全绿（CI 上，而非仅本地）
2. 故事卡片的**每条验收标准**都有可演示的满足证据（命令输出 / 截图 / 测试名）
3. 代码可读性达标：模块有 docstring、非显然逻辑有注释说明**约束**（而非复述代码）
4. CHANGELOG.md 已记录用户可感知的变化
5. 无 TODO 裸奔：遗留事项必须登记为 BACKLOG 故事并在代码中标注 `TODO(VG-xxx)`
6. PO 验收通过（里程碑级）或自审通过（故事级，冲刺评审时补验）

## 7. 工程原则

- **YAGNI**：只实现当前故事需要的东西；抽象等到第二个用例出现时再提
- **薄封装隔离框架**：所有 CrewAI 调用收拢在少数模块（teammate.py 等），升级框架只改一处
- **行为测试优先**：测试面向用户可见行为（对话轮次、记忆召回），不 mock 内部函数
- **本地优先红线**：任何新功能不得引入"工作内容出本机"的数据通路（PLAN.md §5.4）
- **小步提交**：一个故事一个分支；发现的范围膨胀拆新故事，不悄悄扩大当前 diff

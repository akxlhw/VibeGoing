## 2. M3 验收标准逐条核对

验收标准（PLAN.md §4 M3）：*伙伴绑定 Claude Code Runtime 完成一个真实编码任务
（改一个 bug），全过程流式回传；换绑 Codex 后同一 Soul 继续指挥，任务台账完整。*

| 验收要素 | 结果 | 证据 |
|---|---|---|
| Runtime 抽象定稿并配 ADR | ✅ | `runtimes/base.py`（TaskSpec/RuntimeEvent/TaskHandle/Runtime）+ [ADR-0007](../../adr/0007-runtime-abstraction.md)；`test_runtime_is_abstract` 等基础 6 例 |
| 命令契约（claude -p … stream-json / codex exec） | ✅ | `test_command_contract_and_streaming`：argv 精确匹配 + cwd 传入；`test_codex_command_contract_and_output` |

## 4. PO 演示指引（真实链路，需本机安装对应 CLI 并配置 Key）

```bash
# 1) 健康检查（确认 claude/codex 在 PATH）
uv run vibegoing runtime list
# 2) 创建绑定 Claude Code 的伙伴并派真实编码任务
uv run vibegoing soul create dev --persona "编码伙伴" --runtime claude-code --capabilities "工程"
cd <你的项目目录>  # 白名单默认=当前目录
uv run vibegoing --soul dev
> 修复 README 里断掉的链接   # 全程流式回传
# 3) 换绑 Codex，同一伙伴继续（换引擎不换大脑）
uv run vibegoing soul edit dev --runtime codex
uv run vibegoing --soul dev
# 4) 台账回看
uv run vibegoing crew status
```

## 5. 已知限制（ADR-0007 已声明）

| 限制 | 影响 | 解决 |
|---|---|---|
| 超时判定在行间进行 | 完全无输出的僵死进程在首行/EOF 前不会被杀 | ADR-0007 记录；后续版本可加无输出看门狗 |
| stream-json 解析基于当前 claude CLI 契约 | 上游协议漂移需改解析 | 解析集中在 parse_line 单方法；VG-306 契约矩阵排期 |
| 真实链路验收依赖本机 CLI 与 Key | 机制层已全自动验证，真实体验为 PO 演示项 | §4 指引 |

# ADR 0003：飞书接入后置至最后一个里程碑（M5）

- 状态：已采纳（2026-09-06，PO 决策）
- 关联：PLAN.md v1.1 变更记录

## 背景

原规划 v1.0 将飞书网关排在 M2。飞书接入依赖开放平台的审核与权限流程，且协作面价值必须建立在单伙伴体验、多伙伴协作与 CLI Runtime 三块地基之上。

## 决策

M1–M4 全部在本地终端/CLI/桌面完成，飞书（网关、群 @、文档交付、卡片审批）合并为最后一个里程碑 M5。

## 理由

- M1–M4 无一依赖飞书，可独立交付价值；后置使平台审核风险不再阻塞任何早期节奏
- 价值主线更聚焦：终端产品 → 多伙伴 → Coding Agent 执行体 → 桌面应用 → 平台协作面
- M2 的能力路由显式设计为可复用（M5 群内 @ 场景），前期投入不浪费

## 后果与约束

- M2/M3 的验收场景全部使用本地命令（`vibegoing crew run` 等）表述，不出现飞书
- M4 桌面化验收不含"登录飞书"步骤
- M5 预估 6–10 人日（合并原 M2 与原 M5 的飞书交付项）
